Современный, быстрый и безопасный веб-интерфейс для управления серверами Rust через протокол Websocket (WebRcon). Разработан с использованием **Next.js** и **Tailwind CSS**.

🔗 **[Демо](https://rcon.aristocratos.ru/)**

![Preview](./public/og-image.png)

## Особенности

- **Без бэкенда:** IP, порт и пароль обрабатываются только в вашем браузере и уходят напрямую на ваш Rust-сервер. На демо-сайте подключена Vercel Analytics: она собирает анонимную статистику посещений, но не данные подключения.
- **Realtime:** Мгновенное получение логов и отправка команд через WebSockets.
- **История команд:** Стрелки ↑/↓ листают ранее отправленные команды (история сохраняется в браузере).
- **Запоминание сервера:** Последние IP и порт подставляются автоматически. Пароль не сохраняется.
- **Современный UI:** Темная тема, адаптивный дизайн, красивая типографика.
- **Подсветка синтаксиса:** Автоматическое определение типов сообщений (Chat, Warning, Error, Generic).

## Установка и запуск

Для запуска проекта локально вам потребуется [Node.js](https://nodejs.org/) версии 20.9+.

1. **Клонируйте репозиторий:**

   ```bash
   git clone https://github.com/hammzat/rustrcon.git
   cd rustrcon
   ```

2. **Установите зависимости:**

   ```bash
   npm install
   # или
   yarn install
   # или
   pnpm install
   ```

3. **Запустите сервер разработки:**

   ```bash
   npm run dev
   ```

4. Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## Настройка сервера Rust

Чтобы подключиться к серверу через этот клиент, сервер Rust должен быть запущен с поддержкой WebRcon. Добавьте следующие параметры в файл запуска (`.bat` / `.sh`) или `server.cfg`:

```text
+rcon.web 1
+rcon.port 28016
+rcon.password "ваш_пароль"
```

## Безопасность

WebRcon в Rust работает поверх обычного `ws://` без шифрования: пароль передается в URL подключения, а команды и логи идут по сети открытым текстом. Поэтому:

- при открытии клиента по HTTPS браузер блокирует такое подключение (mixed content), и его нужно разрешить вручную (инструкция есть в интерфейсе, кнопка «?»);
- не подключайтесь через публичные или недоверенные сети;
- самый надежный вариант — запустить клиент локально (`npm run dev` или `npm run build && npm start`) по `http://localhost`, тогда mixed content не мешает, или поставить перед сервером TLS-прокси.
